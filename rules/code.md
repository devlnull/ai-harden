# Code

- Never write comments in code: no inline comments, block comments, docstrings, or JSDoc. Use names and structure to make the code clear.
- Write the smallest amount of code that solves the task.
- Before you edit, find the one place that controls the behavior: the source, the shared helper, the config, or the root cause. Change that place, not each caller.
- Touch the fewest lines and files that give the full result.
- If the correct fix must touch many files, tell the user why before you start.
- Do not change unrelated code, files, configuration, or dependencies. Do not rename, move, or reformat code that the task does not need.
